# Структура проєкту ПЕРУКАР

Дата: 2026-05-12

## 1. Загальна структура PERUKAR

PERUKAR — локальний репозиторій застосунку ПЕРУКАР. У корені є правила агента, WWW-версія інтерфейсу, окрема коренева логіка, Android/Capacitor-обгортка, документація, тести, snapshot-папки та службові файли.

## 2. Основні папки

- `www/` — локальна WWW-версія UI та активна WWW-логіка.
- `docs/` — документація поточного стану, QA Smoke Test і майбутні технічні нотатки.
- `android/` — Android/Capacitor-проєкт.
- `project_snapshot/` — раніше створений snapshot проєкту.
- `chatgpt_upload_ready/` — підготовлений пакет або копія для передачі/аналізу.
- `.vscode/`, `.idea/` — налаштування локальних IDE.
- `.venv/`, `node_modules/` — локальні залежності та середовища, не змінювати без окремої задачі.

## 3. Основні файли

- `AGENTS.md` — правила роботи агента в PERUKAR.
- `package.json` — npm scripts і залежності.
- `capacitor.config.json` — конфігурація Capacitor.
- `www/index.html` — HTML-сторінка локального WWW UI.
- `www/core.js` — активна WWW-логіка, розрахунки, блокування і renderer для WWW UI.
- `www/style.css` — стилі WWW UI.
- `core.js` — окрема коренева логіка проєкту.
- `expert_logic.js` — окрема експертна логіка.
- `index.html`, `style.css`, `sw.js`, `manifest.json` — кореневі web/PWA-файли.
- `test_www_render_runtime.js`, `test_www_mapping.js`, `test_math.js`, `test_midband.js`, `test_e2e_local.js` — наявні тестові та перевірочні файли.
- `patch_core.js`, `patch_core2.js`, `patch_core3.js`, `patch_ui.js` — patch-файли або проміжні робочі матеріали.

## 4. Де знаходиться UI

Локальний WWW UI знаходиться у `www/index.html` і використовує `www/core.js` та `www/style.css`.

Кореневий `index.html` також існує, але поточна ручна smoke-перевірка виконувалася для WWW UI.

## 5. Де знаходиться активна WWW-логіка

Активна WWW-логіка знаходиться у `www/core.js`.

Саме там розташовані:
- читання значень з форми;
- вибір рецепта;
- блокування ризикових сценаріїв;
- розрахунок мас;
- renderer для виводу результату в `#output`.

## 6. Де знаходиться документація

Документація знаходиться у `docs/`.

Поточні документи:
- `docs/QA_SMOKE_2026-05-12.md`;
- `docs/PROJECT_STATE_2026-05-12.md`;
- `docs/PROJECT_STRUCTURE_2026-05-12.md`.

Також у корені є `PROJECT_STATE.md`, а в snapshot-папках є копії попередніх станів.

## 7. Де потенційно мають бути тести

Поточні тестові файли лежать у корені репозиторію.

Для майбутнього впорядкування можна окремо розглянути папку `tests/`, але без окремої задачі структуру тестів змінювати не потрібно.

## 8. Які файли не можна чіпати без окремої задачі

- `.env` — може містити локальні або чутливі значення.
- `www/core.js` — активна логіка розрахунків і виводу.
- `core.js` — окрема коренева логіка.
- `expert_logic.js` — експертна логіка.
- `package.json` і `package-lock.json` — залежності та scripts.
- `android/` — Android/Capacitor-частина.
- `project_snapshot/` і `chatgpt_upload_ready/` — snapshot/архівні матеріали.
- `patch_core.js`, `patch_core2.js`, `patch_core3.js`, `patch_ui.js` — проміжні patch-матеріали.

## 9. Зони підвищеного ризику

- `www/core.js`;
- формули;
- вибір типу барвника;
- блоки ризиків;
- клієнтські дані;
- сценарії Special Blond;
- майбутня логіка передпігментації;
- сценарії виходу з чорного.

## 10. Наступний рекомендований крок після документації структури

Наступний безпечний крок — створити snapshot поточного стану документації та коду без зміни бізнес-логіки.

Після snapshot можна окремо описати архітектуру, а вже потім переходити до фази "Ремонт бізнес-логіки" для сценаріїв Special Blond, передпігментації та виходу з чорного.

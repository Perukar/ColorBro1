# Manual Test Spec: ENDS REC / MASS MODEL

Дата: 2026-05-12

## 1. Мета

Підготувати безпечну специфікацію перед майбутнім додаванням окремого рецепта кінців `endsRec` і 3-зонної mass model.

## 2. Поточний стан

- Є `rootRec`.
- Є `lenRec`.
- `endsRec` ще не існує.
- Є `totalMass`.
- Поточний розподіл маси: `rootMass` 30%, `lengthMass` 70%.
- Кінці зараз входять у `lengthMass`.
- Є поля:
  - `ends_level`;
  - `ends_condition`;
  - `ends_history`;
  - `ends_base_type`.
- Кінці зараз використовуються тільки для manual/diagnostic guard.

## 3. Що заборонено без окремої фази

- Створювати approved `endsRec` без mass model.
- Додавати окремий оксид кінців без тестів.
- Додавати окрему формулу кінців без тестів.
- Подвоювати масу продукту.
- Віднімати масу кінців від довжини без перевірки суми.
- Автоматизувати ризикові кінці:
  - косметичний пігмент;
  - темний косметичний пігмент;
  - після змивки;
  - хна / метали;
  - невідома історія;
  - ламкі / критично пошкоджені;
  - невідомий стан.

## 4. Очікувана майбутня 3-зонна mass model

При активному `endsRec` сума має бути контрольована:

- `rootMass + lengthMass + endsMass === totalMass`

Або з допустимою похибкою округлення не більше 1 г.

Можливий стартовий розподіл для тестування:

- rootMass: 25%
- lengthMass: 45%
- endsMass: 30%

Але це тільки test candidate, не затверджена бізнес-логіка.

## 5. Manual-only сценарії

Ці сценарії не мають автоматично створювати approved `endsRec`:

- косметичні кінці + освітлення;
- темний косметичний пігмент на кінцях;
- кінці після змивки;
- хна / метали;
- невідома історія кінців;
- ламкі кінці;
- критично пошкоджені кінці;
- різний рівень кінців + не вказаний стан / історія / тип бази.

## 6. Потенційно low-risk сценарії для майбутньої автоматизації

Тільки після окремих тестів:

- здорові натуральні кінці;
- ends_history: натуральні;
- ends_base_type: натуральна;
- ends_condition: здорові;
- тонування без підйому;
- легка корекція без порошку;
- однаковий або близький процес із довжиною.

## 7. Майбутні business tests

Перед будь-яким кодом потрібні тести:

- MASS-MODEL-3-ZONES-TOTAL
- MASS-MODEL-ROUNDING
- ENDS-REC-NOT-CREATED-WITHOUT-MASS
- ENDS-REC-AUTO-TONING-LOW-RISK
- ENDS-REC-BLOCK-COSMETIC-LIFT
- ENDS-REC-BLOCK-DAMAGED-ENDS
- ENDS-REC-BLOCK-UNKNOWN-HISTORY
- ENDS-REC-POWDER-SURCHARGE-PER-ZONE

## 8. Очікувана безпечна поведінка зараз

До впровадження mass model система має:
- не створювати `endsRec`;
- не показувати approved-рецепт кінців;
- переводити ризикові кінці в `MANUAL_REQUIRED`;
- прямо пояснювати, що окремий рецепт кінців ще не рахується.

## 9. Наступний крок після документа

Після manual spec:
1. додати diagnostic business tests для mass model;
2. тільки потім планувати мінімальний refactor mass model;
3. тільки після цього думати про `endsRec`.

# Поточний стан проєкту ПЕРУКАР

Дата: 2026-05-12

## 1. Поточна назва проєкту

- ПЕРУКАР — офіційна назва продукту українською.
- PERUKAR — технічна назва папки / репозиторію.
- perukar — технічний slug для коду або службових назв, якщо потрібен lowercase-ідентифікатор.

## 2. Поточний стан

- `AGENTS.md` створений і оновлений.
- Правила агента діють для роботи в репозиторії PERUKAR.
- QA Smoke Test збережений у `docs/QA_SMOKE_2026-05-12.md`.
- Робоча папка перед початком цієї документаційної фази була чиста.

## 3. Відомі ключові файли

- `AGENTS.md` — правила роботи агента в проєкті.
- `docs/QA_SMOKE_2026-05-12.md` — результат проведеного QA Smoke Test.
- `www/core.js` — основна WWW-логіка інтерфейсу та рендера.
- `www/index.html` — локальна WWW-сторінка для ручної перевірки UI.
- `test_www_render_runtime.js` — runtime-перевірки WWW renderer-а та DOM-mock сценаріїв.
- `package.json` — npm scripts і залежності проєкту.
- `core.js` — окрема коренева логіка, яка не змінювалася під час поточної документаційної фази.

## 4. Що вже перевірено

- базове відкриття `index.html`;
- консоль браузера;
- активність кнопок;
- базовий APPROVED-сценарій;
- BLOCKED-сценарій для небезпечної комбінації.

## 5. Що НЕ доведено

- правильність усіх формул;
- правильність вибору типу барвника;
- готовність алгоритму до реальної експлуатації;
- коректність логіки Special Blond.

## 6. Відомі ризики

- сценарій 6 → 8.3 активує Special Blond;
- мовна мішанина UA/RU;
- неповні дані можуть давати 0 або порожні поля;
- потрібен автоскрол або фокус на результат після генерації протоколу.

## 7. Важливо

Special Blond 6 → 8.3 поки тільки діагностовано. Код не змінювався.

Цю тему потрібно перенести у майбутню фазу "Ремонт бізнес-логіки".

## 8. Наступні фази

- завершити документацію структури;
- створити snapshot поточного стану;
- описати архітектуру;
- потім окремо перейти до ремонту бізнес-логіки.

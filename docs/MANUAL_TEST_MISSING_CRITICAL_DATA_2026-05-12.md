# Manual test spec: MISSING-CRITICAL-DATA

## 1. ID сценарію

MISSING-CRITICAL-DATA

## 2. Назва

Відсутні критичні дані для розрахунку рецепта.

## 3. Мета

Перевірити, що система не рахує фінальний рецепт як точний, якщо не заповнені критичні вхідні дані.

## 4. Вхідні дані

Один або кілька критичних параметрів відсутні:

- натуральна база;
- поточний рівень;
- бажаний рівень;
- історія фарбування.

Інші поля можуть бути заповнені нейтральними значеннями, щоб перевірка фокусувалась саме на відсутності критичних даних.

## 5. Поточна поведінка / що треба перевірити

Перевірити, чи система:

- не підставляє небезпечні припущення замість відсутніх критичних даних;
- не формує точний рецепт при неповному input;
- не показує результат як безумовно затверджений;
- явно повідомляє, які дані відсутні або потребують уточнення.

## 6. Очікувана безпечна поведінка

Система має повернути `insufficient_data`, blocking warning або `MANUAL_REQUIRED`.

Фінальний рецепт не має виглядати як точний протокол, якщо критичні дані не заповнені.

## 7. Рівень ризику

HIGH.

## 8. Що перевіряє сценарій

- Валідацію критичних вхідних даних.
- Блокування або ручний контроль при неповному input.
- Відсутність точного рецепта на основі припущень.
- Коректне повідомлення про причину неможливості точного розрахунку.

## 9. Поточний статус

Manual test spec створено, автоматичний тест ще не реалізовано, бізнес-логіка ще не змінювалась.

## 10. Наступний крок

Підготувати автоматичний діагностичний тест для сценарію `MISSING-CRITICAL-DATA`, який перевіряє блокування точного рецепта при відсутніх критичних даних.

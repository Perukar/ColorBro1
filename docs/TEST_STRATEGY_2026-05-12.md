# Тестова стратегія ПЕРУКАР

Дата: 2026-05-12

## 1. Мета тестової стратегії

- Не допустити зміни бізнес-логіки без перевірки конкретним сценарієм.
- Відділити UI smoke test від колористичних логічних тестів.
- Підготувати безпечний перехід до фази “Ремонт бізнес-логіки”.

## 2. Поточний стан

- Базове впорядкування проєкту завершене.
- QA Smoke Test є і зафіксований у `docs/QA_SMOKE_2026-05-12.md`.
- Код і алгоритми поки не змінювались у межах підготовки тестової стратегії.

## 3. Типи тестів

- Smoke test інтерфейсу — перевіряє, що UI відкривається, кнопки працюють, результат з’являється.
- Синтаксична перевірка JS — перевіряє, що JS-файли не мають синтаксичних помилок.
- Runtime-перевірка рендера — перевіряє renderer і контрольовані DOM-mock сценарії.
- Бізнес-сценарії колористики — перевіряють конкретні рішення алгоритму.
- Регресійні тести після кожної правки — перевіряють, що попередні сценарії не зламалися.

## 4. Мінімальні перевірки перед будь-якою правкою логіки

- `git status --short`;
- `node --check www/core.js`;
- наявні `test_www_*.js`, якщо існують;
- окремий сценарій для конкретної бізнес-логіки, яку змінюємо.

## 5. Обов’язкові бізнес-сценарії для майбутніх тестів

- 6 → 8.3 і Special Blond;
- 10 → 6 і передпігментація;
- вихід із чорного;
- різні зони: корінь / довжина / кінці;
- невідома історія фарбування;
- пошкоджене волосся + високий оксид;
- неповні критичні дані;
- сивина 50%+;
- косметична база на довжині.

## 6. Правило для змін бізнес-логіки

Кожна зміна бізнес-логіки має супроводжуватись хоча б одним тестовим сценарієм або чітко описаною ручною перевіркою.

Якщо тестовий сценарій неможливо автоматизувати одразу, потрібно письмово зафіксувати ручну перевірку, очікуваний результат і залишковий ризик.

## 7. Що заборонено

- Правити `www/core.js` без тестового сценарію.
- Змішувати рефакторинг і зміну алгоритму.
- Комітити код без перевірки.
- Називати smoke test доказом правильності колористичної логіки.

## 8. Наступний крок після документа

- Створити список бізнес-сценаріїв для тестів.
- Тільки після цього відкривати фазу “Ремонт бізнес-логіки”.
